# Spec Persistence and Download

Persist generated specs with Vercel Blob and Prisma, then add a secure download
route so users can retrieve their generated spec files.

## Implementation

1. ProjectSpec model (`prisma/models/project.prisma`)

   Ensure a `ProjectSpec` Prisma model exists with:

   - `id` — String, `@id @default(cuid())`
   - `projectId` — String (relation to `Project` via `@relation(fields: [projectId], references: [id], onDelete: Cascade)`)
   - `project` — Relation to `Project` (back-reference: `specs ProjectSpec[]`)
   - `filePath` — String (Vercel Blob URL, e.g., `https://<blob-store>.public.blob.vercel-storage.com/specs/<projectId>/<specId>.md`)
   - `createdAt` — DateTime `@default(now())`
   - Index: `@@index([projectId, createdAt])`

   The `Project` model includes `specs ProjectSpec[]` relation.

   Use this model for metadata only. The actual spec content lives in Vercel Blob.

1. Save generated spec (in `trigger/generate-spec.ts`)

   After a spec is generated by the AI:

   - Generate a unique `specId` using `crypto.randomUUID()`
   - Upload the Markdown content to Vercel Blob using `put()` from `@vercel/blob`:
     - Path: `specs/${roomId}/${specId}.md` (roomId = projectId)
     - Options: `{ access: "private", addRandomSuffix: false, allowOverwrite: true, contentType: "text/markdown; charset=utf-8", cacheControlMaxAge: 60 }`
     - Returns a `blob` object with `url` property (the Blob URL)
   - Upsert the `ProjectSpec` record in Prisma:

     ```typescript
     await prisma.projectSpec.upsert({
       where: { id: specId },
       create: { id: specId, projectId: roomId, filePath: blob.url },
       update: { filePath: blob.url },
     });
     ```

   - The `filePath` stores the full Vercel Blob URL for later retrieval
   - Follow the same metadata + blob pattern used for canvas persistence (`Project.canvasJsonPath`)

1. Spec list route (`GET /api/projects/[projectId]/specs`)

   Create `app/api/projects/[projectId]/specs/route.ts`:

   - Authenticate user via Clerk (`auth()`)
   - Resolve Clerk identity via `getCurrentClerkIdentity()`
   - Verify project access via `findAccessibleProjectForViewer(projectId, identity)` (owner or collaborator)
   - Query `prisma.projectSpec.findMany({ where: { projectId: project.id }, orderBy: { createdAt: "desc" }, select: { id: true, createdAt: true, filePath: true } })`
   - Transform each spec to include `filename` derived from `filePath` (e.g., `spec.md` from the URL path)
   - Return `{ specs: [{ id, createdAt (ISO string), filename }] }`

1. Download route (`GET /api/projects/[projectId]/specs/[specId]/download`)

   Create `app/api/projects/[projectId]/specs/[specId]/download/route.ts`:

   - Authenticate user via Clerk (`auth()`)
   - Resolve Clerk identity via `getCurrentClerkIdentity()`
   - Verify project access via `findAccessibleProjectForViewer(projectId, identity)`
   - Fetch the spec record: `prisma.projectSpec.findFirst({ where: { id: specId, projectId: project.id } })`
   - If not found, return `404 Spec not found`
   - Fetch the file from Vercel Blob using `get(spec.filePath, { access: "private", useCache: false })`
   - If blob not found, return `404 Spec not found`
   - Return a `Response` with the blob stream and headers:
     - `Content-Disposition: 'attachment; filename="spec.md"'`
     - `Content-Type: "text/markdown; charset=utf-8"`
   - Handle errors: return `502 Unable to download spec` on blob fetch failures

## Scope Limits

- Do not add frontend or UI logic (covered in 29-spec-ui-integration)
- Do not store spec content in Prisma (only metadata + Blob URL)
- Do not expose Blob URLs directly to the client without access checks
- Do not modify existing canvas persistence

## Notes

- Check `context/project-overview.md` and `context/architecture.md` first
- Reuse existing project access patterns (`findAccessibleProjectForViewer`, `getCurrentClerkIdentity` from `lib/project-access.ts`)
- Prisma stores metadata, Vercel Blob stores content
- Blob URLs are private and only accessible via the download route with proper auth
- The `cacheControlMaxAge: 60` on blob upload allows brief caching for preview
- Spec filenames are derived from the blob path (last segment) for display

## Check When Done

- `ProjectSpec` model exists with required fields and relations
- Spec is uploaded to Vercel Blob at `specs/{projectId}/{specId}.md`
- `filePath` (Blob URL) is saved correctly in Prisma
- `GET /api/projects/[projectId]/specs` returns spec metadata with filenames
- Download route validates project access and spec ownership before returning file
- Download response is a Markdown attachment with proper headers
- TypeScript and build pass
